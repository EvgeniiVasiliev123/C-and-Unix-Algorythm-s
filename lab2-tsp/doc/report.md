# Отчёт по лабораторной работе № 2

## Структуры данных и динамическое программирование

**Тема:** поиск кратчайшего замкнутого маршрута (задача коммивояжёра).

## 1. Цель работы

Познакомиться с основами структур данных и методами динамического программирования на примере задачи поиска кратчайшего замкнутого маршрута через заданные точки.

## 2. Постановка задачи

Заданы `n` точек на плоскости координатами `(xᵢ, yᵢ)`. Необходимо найти маршрут, который:

1. начинается в первой введённой точке;
2. посещает каждую из остальных точек ровно один раз;
3. возвращается в исходную точку;
4. имеет минимальную суммарную длину.

Расстояние между точками вычисляется по евклидовой формуле:

`d(i, j) = sqrt((xᵢ - xⱼ)² + (yᵢ - yⱼ)²)`.

## 3. Проектирование структуры данных

Для хранения координат используется `vector<Point>`, где `Point` содержит две координаты типа `double`. Для ускорения вычислений заранее строится матрица расстояний `cost[n][n]`.

Основная структура алгоритма — таблица динамического программирования `dp[mask][last]`:

- `mask` — битовая маска посещённых точек; бит `i` равен 1, если точка `i` уже входит в маршрут;
- `last` — индекс последней посещённой точки;
- `dp[mask][last]` — минимальная длина пути из точки 0 в `last`, который посещает ровно множество точек `mask`.

Для восстановления оптимального маршрута используется компактный массив `parent[mask][last]`, в котором хранится предыдущая точка оптимального состояния. Индекс ячейки обеих таблиц вычисляется линейно: `mask * n + last`. Это позволяет хранить таблицы в непрерывных векторах без дополнительных объектов для каждой пары состояния.

Тип `double` применяется для расстояний, а `int8_t` — для предка: при ограничении `n ≤ 18` индекс вершины помещается в один знаковый байт (значение `-1` означает отсутствие предка). Матрица расстояний требует `O(n²)` памяти.

## 4. Алгоритм динамического программирования Held–Karp

Начальное состояние: `dp[1][0] = 0`, поскольку посещена только первая точка и длина пути равна нулю. Все остальные состояния изначально имеют значение бесконечности.

Переход. Для каждого достижимого состояния `(mask, last)` рассматривается ещё не посещённая точка `next`, отличная от стартовой. Новое состояние получается добавлением её бита:

`nextMask = mask | (1 << next)`.

Кандидат на улучшение:

`candidate = dp[mask][last] + cost[last][next]`.

Если кандидат меньше текущего значения `dp[nextMask][next]`, значение обновляется, а `parent[nextMask][next]` получает `last`.

После заполнения таблицы все точки посещены. Чтобы замкнуть маршрут, к каждому состоянию последней точки добавляется расстояние обратно до точки 0. Выбирается минимум:

`best = min(dp[full][last] + cost[last][0])`, где `full = 2ⁿ - 1`.

Оптимальный маршрут восстанавливается обратным проходом по `parent`, при каждом шаге из маски исключается бит текущей точки. Полученная последовательность разворачивается и дополняется стартовой точкой в конце.

Для `n = 1` отдельно возвращается маршрут `0 → 0` длины 0.

## 5. Оценка вычислительных и ёмкостных затрат

Число масок равно `2ⁿ`. Для каждой маски рассматривается до `n` возможных последних точек и до `n` переходов. Поэтому временная сложность алгоритма составляет **`O(n² · 2ⁿ)`**. Это существенно лучше полного перебора `O((n−1)!)` при росте числа точек, хотя задача остаётся экспоненциальной.

Таблицы `dp` и `parent` содержат по `n · 2ⁿ` элементов. Следовательно, дополнительная память — **`O(n · 2ⁿ)`**. Матрица расстояний занимает `O(n²)` памяти и не меняет итоговую оценку.

При максимуме `n = 18`:

- число ячеек DP: `18 · 2¹⁸ = 4 718 592`;
- таблица `double`: `4 718 592 · 8 = 37 748 736` байт;
- таблица предков `int8_t`: `4 718 592` байт;
- вместе: `42 467 328` байт, приблизительно **40.5 MiB**;
- матрица расстояний из 324 элементов занимает ещё около 2.5 KiB.

Ограничение в 18 точек задано с учётом экспоненциального роста таблиц и практического расхода памяти.

## 6. Реализация программы

- `src/tsp.hpp` содержит структуры данных, вычисление расстояний, DP Held–Karp, восстановление маршрута и эталонный полный перебор для тестов.
- `src/main.cpp` читает координаты из файла или стандартного ввода, поддерживает генерацию случайных точек, запускает алгоритм и выводит найденный маршрут, длину и время работы.
- `src/test.cpp` сравнивает результат DP с полным перебором для малых наборов точек, а также проверяет, что маршрут начинается и заканчивается в точке 0 и посещает каждую точку ровно один раз.
- `Makefile` содержит цели сборки, запуска, тестирования и очистки.

Поддерживаются строки формата `X Y`, `номер X Y` и `Точка 1, X, Y`; строки-комментарии начинаются с `#`. Для координат используются два последних числовых значения строки.

## 7. Проверка работы

**Результат запуска `make run` на `data/example.txt` (8 точек):**

- оптимальный маршрут: `1 → 2 → 3 → 4 → 5 → 6 → 8 → 7 → 1`;
- длина маршрута: `28.053` (округлено до трёх знаков);
- измеренное время одного запуска: `0.031 мс` в текущем тестовом окружении; время зависит от компьютера и нагрузки.

## 8. Вывод

В ходе лабораторной работы спроектирована компактная структура хранения состояний на основе битовой маски и линейных массивов, реализован точный алгоритм динамического программирования Held–Karp для задачи коммивояжёра. Реализовано восстановление маршрута по массиву предков, ввод координат и вывод результата. Корректность проверена сравнением с полным перебором на 1805 тестовых наборах. Получены оценки сложности `O(n² · 2ⁿ)` по времени и `O(n · 2ⁿ)` по памяти.
