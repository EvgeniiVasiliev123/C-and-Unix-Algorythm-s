## [СОРТ 1] Сортировка подсчётом

### 1. Постановка задачи

После экзамена нужно построить итоговую ведомость: отсортировать **100 000 оценок** (целые числа от 0 до 100) по возрастанию.

Особенности данных:
- значения целые;
- диапазон очень мал: `k = 101`, при этом `n = 100 000`, то есть `k << n`;
- одинаковых значений очень много.

### 2. Выбор алгоритма и обоснование

Выбран алгоритм **сортировки подсчётом**.

1. Алгоритмы, основанные на сравнениях (слиянием, быстрая, кучей), не могут быть быстрее, чем `Ω(n log n)`. Для `n = 100 000` это порядка `100 000 · log2(100 000) ≈ 1,66 · 10^6` сравнений.
2. Сортировка подсчётом не использует сравнений и работает за `O(n + k)`. При `k = 101` это порядка `2 · 10^5` операций, то есть примерно в 8 раз меньше, чем нижняя граница для сравнительных сортировок.
3. Дополнительная память не зависит от n: 101 счётчик, около 404 байт (int - 4 байта).
4. Простая реализация.

Простые квадратичные сортировки (пузырьком, выбором, вставкой) для `n = 100 000` потребовали бы порядка `n² / 2 = 5 · 10^9` операций и заведомо хуже.

Условие применимости: значения - целые числа из ограниченного, небольшого диапазона. Если бы `k` было сравнимо с `n²` или значения были вещественными, выбор был бы другим.



### 3. Результат запуска (n = 100 000, k = 101)

```
Массив отсортирован: да
Время: ~0,05 мс
```

Время зависит от компьютера, значение приведено для примера.

## [СОРТ 2] Сортировка вставкой

### 1. Постановка задачи

Есть таблица рейтинга участников соревнования, которая уже была отсортирована по результату. После очередного тура результаты у небольшого числа участников изменились, причём слегка: каждый сместился лишь на несколько позиций. Требуется быстро вернуть таблицу в отсортированное состояние, не выделяя дополнительную память.

Для эксперимента: `n = 10 000`, в идеально отсортированном массиве случайно переставлено 1 % соседних пар (100 перестановок).

### 2. Выбор алгоритма и обоснование

Выбрана **сортировка вставкой**. Условие ЛР выполнено: её асимптотика в худшем случае `O(n²)` больше, чем у СОРТ 1 (`O(n + k)`).

Почему она лучший выбор именно для этой задачи:

1. **Адаптивность.** Время работы `O(n + I)`, где `I` - число инверсий. Массив почти отсортирован, значит `I` мало, и алгоритм работает почти за линейное время.
2. **Память `O(1)`**: сортировка на месте, нужны только две переменные (`key`, `j`).
3. **Устойчивость:** участники с равными результатами сохраняют прежний порядок.
4. Сортировка подсчётом не подходит: ключи не из малого диапазона.

Сравнение с альтернативами для `n = 10 000` на почти отсортированных данных:

| Алгоритм | Сравнений (порядок) | Доп. память |
|---|---|---|
| Вставкой | ≈ n + I ≈ **10 097** (измерено) | O(1) |
| Слиянием | ≈ n·log2(n) ≈ 132 877 (не зависит от порядка) | O(n) |
| Пузырьком (без проверки обменов) | ≈ n²/2 = 50 000 000 | O(1) |

Сортировка вставкой делает примерно в 13 раз меньше сравнений, чем слиянием, и не требует дополнительной памяти.

Ограничение: на случайных или обратно упорядоченных данных алгоритм квадратичный и использовать его нельзя (см. измерения ниже).

## Вывод

Выбор алгоритма сортировки зависит от свойств данных, а не от того, что «быстрая сортировка лучше всех». Сортировка подсчётом выигрывает у любых сравнительных сортировок при малом диапазоне целых значений. Сортировка вставкой, хотя и квадратична в худшем случае, оптимальна для почти отсортированных данных. Анализ времени и памяти позволяет обосновать выбор заранее.
